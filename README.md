# Profi Reply Bot

Telegram-бот для персональных откликов на Профи.ру. Принимает текст, фото и файлы JPG/PNG/WebP до 10 МБ. Создаёт один ответ до 500 символов. Для вакансий тоже создаёт ответ, предупреждение размещает отдельно от цитаты.

## Возможности

- Готовый ответ в HTML-цитате. Короткие ответы копируются кнопкой, длинные открываются отдельным блоком для копирования.
- Пользователи, первый и последний источник, обращения, генерации, ошибки и расход токенов сохраняются в базе.
- Ссылки вида `https://t.me/ИМЯ_БОТА?start=insta_bio` позволяют учитывать источник. Если параметра нет, источник `direct`; Telegram не сообщает откуда человек фактически открыл обычную ссылку.
- Админка внутри Telegram: `/admin`, `/users`, `/user ID`, `/sources`, `/source название`, `/export`, `/profile`, `/set_profile текст`, `/block ID`, `/unblock ID`.
- Доступ в админку по разрешённому Telegram ID или одноразовой секретной ссылке. Первый случайный пользователь администратором не становится.
- Дневные лимиты: 30 обращений к ИИ на человека, 300 суммарно; повторное сокращение также считается вызовом.
- Повторная доставка одного Telegram update не запускает новую генерацию. Входящие подтверждаются только после сохранения в БД.
- После перезапуска очередь восстанавливается; оборванную генерацию бот просит прислать повторно, не повторяет платный вызов незаметно.

## Завершение запуска на существующем Render

1. Загрузить файлы из этого архива в корень существующего репозитория, заменив старые. В корне должны быть `Dockerfile`, `requirements.txt`, `app.py`, `db_pg.py`, `webhook.py` и остальные файлы. Сам ZIP в репозиторий загружать не нужно.
2. В настройках созданной базы Render открыть Connections и скопировать Internal Database URL. В Environment созданного веб-сервиса добавить его как `DATABASE_URL`. Не публиковать значение.
3. В Settings сервиса убрать Docker Command override, чтобы использовался `CMD` из Dockerfile, либо указать `python app.py`. Существующая проверочная команда также запустит эту версию, когда `DATABASE_URL` заполнен.
4. Нажать Manual Deploy → Deploy latest commit. Дождаться статуса Live. `/healthz` должен отвечать `ok`, а Telegram `/start` — показывать справку.

Ключи в архив не входят. Настройки перечислены в `.env.example`. Render автоматически предоставляет `RENDER_EXTERNAL_URL`; `PUBLIC_URL` можно указать явно. Для секретов `WEBHOOK_SECRET` и `ADMIN_CLAIM_CODE` подходят случайные значения из `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

## Администратор

Открыть `https://t.me/brovi_en_bot?start=admin_ЗНАЧЕНИЕ_ADMIN_CLAIM_CODE`, нажать Start, затем `/admin`. Код хранится в Environment Render, не в исходниках. Ссылка выдаёт права только первому использовавшему её владельцу. Альтернатива: явно задать `ADMIN_IDS` со своим числовым Telegram ID.

Профиль преподавателя меняется через `/set_profile`. В текущем профиле Константин, информатика и программирование, бесплатная диагностика до 25.10.2026 включительно. После этой даты промпт запрещает предлагать её бесплатно. Неподтверждённые дипломы, стаж и результаты бот не должен выдумывать.

## Ограничения бесплатного размещения

Render Free засыпает после 15 минут без входящих HTTP-запросов. Webhook Telegram будит сервис; первое сообщение после простоя может ждать около минуты. Во время запуска Telegram повторяет доставку, данные и очередь хранятся в PostgreSQL.

Созданная бесплатная база Render действует до **20.11.2026, 20:14 UTC (23:14 МСК)**. Это временное бесплатное размещение, не бессрочная база. До этой даты нужно перенести PostgreSQL или продлить её по условиям Render. OpenAI API оплачивается отдельно согласно балансу предоставленного ключа.

Документация Render: https://render.com/docs/free

## Локальный запуск

Python 3.12+. Установить `python -m pip install -r requirements.txt`. Задать `BOT_TOKEN`, `OPENAI_API_KEY`, `ADMIN_CLAIM_CODE` в окружении. Для локального режима указать `BOT_MODE=polling`, убрать `DATABASE_URL`, задать постоянный `DB_PATH`, затем `python app.py`.

SQLite подходит для компьютера или сервера с постоянным диском. На Render Free использовать только PostgreSQL: локальные файлы там не сохраняются между перезапусками. Одновременно должна работать одна копия polling-бота. Программа не удаляет чужой Telegram webhook автоматически.

## Проверка

`python -m unittest -v test_bot test_webhook`

Интеграционные проверки: задать `TEST_DATABASE_URL` только на отдельную тестовую PostgreSQL, затем `python -m unittest -v test_postgres`. Эти тесты очищают таблицы тестовой базы. На рабочей базе их запускать нельзя. Для localhost без TLS можно явно задать `PGSSLMODE=disable`; в рабочем окружении TLS включён по умолчанию.

Подробности выполненной проверки — `VALIDATION.md`.
